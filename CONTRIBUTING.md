# Contributing to LLM Hallucination Detection & Verification

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/llm-hallucination-detection-and-verification.git`
3. Create a feature branch: `git checkout -b feature/your-feature`
4. Install dependencies: `pip install -r requirements.txt`
5. Make your changes
6. Run tests: `pytest`
7. Commit: `git commit -am 'Add your feature'`
8. Push: `git push origin feature/your-feature`
9. Create a Pull Request

## Development Guidelines

### Code Style
- Follow PEP 8 conventions
- Use type hints for function signatures
- Keep functions focused and single-purpose
- Add docstrings to all public functions

### Testing
- Write unit tests for new features
- Maintain >80% code coverage
- Test edge cases and error conditions
- Use descriptive test names

### Documentation
- Update README.md for user-facing changes
- Add docstrings to all functions
- Include examples in docstrings
- Update DETAILED_DOCUMENTATION.md for major changes

## Submitting Issues

When reporting bugs:
1. Check if issue already exists
2. Provide clear description
3. Include minimal reproducible example
4. Specify Python version and OS
5. Attach relevant error messages

## Submitting Features

When proposing features:
1. Open an issue for discussion first
2. Describe the motivation and use case
3. Discuss implementation approach
4. Get feedback before starting work

## Code Review Process

All PRs must:
1. Pass CI/CD checks
2. Have >80% test coverage
3. Include updated documentation
4. Follow code style guidelines
5. Receive approval from maintainers

## Community

- Be respectful and inclusive
- Help other contributors
- Share knowledge and experience
- Celebrate contributions
